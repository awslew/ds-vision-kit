# 能力盘点与精度测量

这是 vision-core 底座的**实测能力清单**和**精度测量方法**。每一条都来自真实测试
（测试图见 `tests/fixtures`，可在本地复现）。场景层据此决定要做什么、输出时怎么标注。

## 一、实测能力清单

测试图类型：截图文字、带表格的文档图、柱状/折线图（带标注 & 无标注）、真实照片。

| 能力 | 工具 | 实测结论 |
|---|---|---|
| 图像描述/问答 | glance -q | **强**。照片的场景/光线/主体/细节都能准确描述 |
| 逐字 OCR | glance --ocr | **强**。正文、代码、`\n` 字面量都逐字转录 |
| 表格 → Markdown | glance + prompt | **强但需显式 prompt**。数字全对、能验算求和；但整页多表时**会漏靠下的表**，必须用 ocr-extract 的"表格逐个枚举"prompt |
| 图表读数（有标注） | glance -q | **精确**。柱顶标注值原样读出 |
| 图表读数（无标注） | glance -q | **可用**。按刻度线估读误差 ±2% 左右，且系统性略低估；必须标注"近似" |
| 元素定位 | ground | **可用但序数不稳**。`ground "第 3 根柱"` 这类"第几个同类"会错位到邻近实例（实测 Q3 柱定位成 Q2，试多次才偶中）。可靠做法：`detect` 全量枚举（实测 4 根柱坐标全对）→ 按坐标/标签挑目标 → `glance --region` 放大。核心 ground.py 已加序数消歧 prompt（对部分模型有帮助、对非序数无回归），但别依赖它 |
| 元素枚举 | detect | **强**。图例/刻度/组件/数值标注全枚举 + 像素框 |
| 颜色精确 | palette | **精确**。取色号以 palette 为准，不信 glance prose |
| 几何精确 | trace / crop | **像素级**。不走模型 |
| 差异检测 | pixel-diff | **像素级**。差异框直接喂 glance --region |
| 长截图分段 OCR | long-ocr | **可用（本套件已修 Windows 双 bug）**。分段 + 合并 + 边界审计 |
| HTML→截图 | html-shot | **可用**。headless Chrome/Edge |

## 二、精度测量方法（MAPE）

参考 themenonlab 的图表提取验证方法论（references/accuracy.md 来源），严谨地量化
"这个视觉模型读图表有多准"：

1. **构造真值**：用 matplotlib/PIL 从**已知数值**生成测试图（见 tests/fixtures/make_chart*.py）。
2. **提取**：跑 vision-core 命令读图，得到提取值。
3. **算误差**：MAPE = (1/n) × Σ|真值−提取值|/真值 × 100%；准确率 = 100% − MAPE。
4. **换模型/换图**：同一套图换 provider 或模型，对比准确率。

已知数据：有标注柱状图 100% 精确；无标注估读 MAPE ≈ 2%，且系统性低估——实测一组
（真值 240/520/380/710/460/890）全部低于真值（估读 230/500/370/690/440/870），偏差
10-20、模型自报误差范围 20-30。若你的 provider 读不准，先按此方法量化，再决定场景
输出要不要一律标"近似"。

## 三、能力边界（诚实声明）

- 单屏整页 OCR 对下半部分内容有漏读风险 → ocr-extract 用"枚举所有表格/文字块数量"
  prompt 对冲。
- ground 的序数定位不可靠 → image-qa 场景写明了用 detect 兜底。
- 图表无标注估读不是精确数据 → chart-reading 强制标注 estimate + 误差范围。
- 视觉模型会自信地编造像素级细节（颜色、边框、高亮）→ 一切像素级事实交给
  trace/palette/pixel-diff。
